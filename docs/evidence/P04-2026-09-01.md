## Implementation inventory

- `model.m`: bounded, deterministic binary Bayes calculation. It validates a prior, sensitivity,
  false-alarm probability, and reference population before calculations; forms all four joint
  condition/alarm cells; applies the law of total probability; rejects an impossible observed alarm;
  normalizes both alarm sources; exposes prior/posterior odds, LR+, expected counts, units, and named
  errors; and contains no plotting, random draw, toolbox, or population-sized allocation.
- `p04_baseline.m`: one deterministic 1% prior, 90% sensitivity, 10% false-alarm, 10,000-system
  transition. It shows prior/posterior probability and the 90-versus-990 expected alarm-source
  composition, with labeled units and exact replacement of only its owned baseline figure.
- `experiment.m`: a prior `[0.001, 0.010, 0.100]` sweep at fixed likelihoods; an independent
  false-alarm `[0.01, 0.10, 0.30]` sweep after resetting the prior and sensitivity; explanations
  after each view; an equal-prior/base-rate-neglect shortcut shown before a separate prior-weighted
  repair; and tolerance-aware baseline assertions.
- `interactive.m`: bounded prior, sensitivity, and false-alarm sliders; a baseline reset; two
  complementary fixed-scale views; a constant 10,000-system reference calculation; P04-only UI
  replacement; and a captured P04 model handle for callbacks.
- `run_checks.m`: deterministic repetition, independent joint arithmetic, mass conservation, row and
  column totals, posterior normalization, odds form, baseline counts, uninformative evidence,
  endpoints, perfect-specificity/zero-sensitivity limits, two isolated sweeps, broken-case boundary,
  count-scale invariance, caller-RNG isolation/restoration, malformed inputs, impossible evidence,
  and both resource boundaries.
- `tests/test_p04_module.py`: independent Python reference arithmetic for baseline, sweeps, joint
  mass, odds, endpoints, impossible observations, malformed inputs, scale behavior, and resource
  limits. It also retains source-level MATLAB, pedagogy, lifecycle, isolation, compatibility, and
  newline contracts. It does not establish MATLAB numerical fidelity.
- `tests/test_learn_cli.py`: a direct P04 completion fixture invokes the documented command and verifies
  persisted selection, completion, teach-back, resume, status, and list behavior. A separate P04
  rollback fixture scaffolds P04 and every successor, resumes at P03, derives active counts, rejects
  P04 selection, and preserves dormant P04 completion and teach-back data. Existing generic fixtures
  cover malformed state, interruption, cancellation, lock timeout/recovery, concurrent updates, and
  stale artifacts in isolated temporary repositories.

## Independent review repairs

- Replaced exact expected-count equality with tolerances because IEEE-754 evaluation of
  `10000*(0.01*0.90)` is slightly above 90 and would otherwise fail in MATLAB.
- Restored the caller RNG state from the complete `run_checks.m` harness with `onCleanup`; the model
  itself performs no random operation.
- Corrected repeated-evidence guidance: marginal single-alarm likelihood ratios cannot be reused as
  though correlated alarms were independent, while calibrated joint or conditional likelihoods
  remain valid for sequential Bayes updates.
- Added permanent public-table status coverage and P04-plus-successor rollback behavior so retained
  tests remain valid after later batches advance the shared frontier.
- Narrowed `p04_baseline.m` replacement to its exact owned figure; rerunning the baseline no longer
  closes the interactive explorer, sweep figures, or broken/repair views.
- Added the missing direct P04 completion behavior test. The rollback fixture seeds dormant state and
  therefore did not prove that the documented public command persisted P04's attested teach-back.

## Residual risks

- MATLAB parser/runtime compatibility, numerical assertions, figure rendering, UI layout, callbacks,
  and reset behavior remain unverified without the named runtime.
- Static source checks can pin formulas and structure but cannot prove the MATLAB implementation
  evaluates them as intended. Independent Python arithmetic is a separate reference, not MATLAB
  execution.
- The binary table assumes fault/healthy are mutually exclusive and exhaustive and that the stated
  likelihoods are calibrated. A missing condition or population drift can make the posterior
  misleading even when the arithmetic is correct.
- This lesson intentionally updates on one alarm. Reusing the marginal LR+ for correlated repeated
  alarms would double-count evidence; a calibrated joint or conditional likelihood is required.
- Expected counts visualize exact probability mass on a reference scale. They are not sampled data,
  confidence intervals, or evidence about educational effectiveness.
- The forbidden root MATLAB harness still lacks a manifest-status gate and can resolve generic
  `model`/`run_checks` names from an unintended current folder. P04 captures its UI model handle, but
  cross-module dispatch requires a separately authorized repair.
- P04-specific remote Portfolio Control and target Quality workflows did not run because no commit,
  push, or pull request was authorized. Successful baseline/control runs do not validate P04.
- Canonical repository metadata names `kpbianco/*` while active metadata and actual remotes use
  `tranquilWorks/*`; this ownership-name drift is outside allowed paths.
