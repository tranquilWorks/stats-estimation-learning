## Implementation inventory

- `model.m`: bounded deterministic sensor model `X_i = mu + b + sigma*Z_i`; explicit cumulative
  sample mean, target error, random error, `sigma/sqrt(n)` standard error, and
  `sqrt(b^2 + sigma^2/n)` target RMSE. Inputs are validated before count vectors, supplied-vector
  scanning, or random allocation. Seeded calls restore caller RNG state; an optional finite
  standardized-noise vector supports exact fixtures. The function has no plotting, UI, toolbox, or
  population-sized operation above the 50,000-sample cap.
- `p05_baseline.m`: one seeded 400-sample, 12 mV target, 4 mV RMS noise, zero-bias transition. It
  shows raw readings and the running sample mean with labeled sample/mV axes and theoretical
  two-standard-error reference scales. Only its exact owned figure is replaced.
- `experiment.m`: a sample-count `[25 100 400]` sweep reusing one seeded prefix; a reset followed by
  a noise-RMS `[1 4 8] mV` sweep reusing one standardized path; an explicit warning that realized
  error need not be monotone; a `+3 mV` calibration-offset case; and a known-offset repair.
- `interactive.m`: bounded integer-safe sample-count/seed and bounded noise-RMS/bias controls; a
  baseline reset; stable comparison limits that expand to retain extreme valid values; a captured
  P05 model handle; and constant, bounded synchronous work.
- `run_checks.m`: deterministic repetition; independent cumulative arithmetic; exact supplied-noise
  fixtures, including a path whose realized error worsens while standard error shrinks; final-mean
  identity; standard-error/RMSE equations; one-sample and zero-noise limits; seeded prefixes; both
  isolated sweeps; translation; bias failure and repair; RNG isolation; malformed inputs; named
  fixture/domain failures; and accepted/rejected resource boundaries.
- `tests/test_p05_module.py`: independent Python arithmetic on explicit standardized values plus
  direct nonmonotone realized-error behavior plus source-level lifecycle, pedagogy, compatibility,
  resource-order, placeholder, opaque-toolbox, and terminal-newline contracts. It does not establish
  MATLAB numerical fidelity.
- `tests/test_learn_cli.py`: direct P05 completion/resume/status/list behavior and a future-durable
  rollback fixture that scaffolds P05 and every successor, resumes P04, derives active counts,
  rejects stale P05 checks, and preserves dormant P05 completion and teach-back data. Existing
  generic fixtures cover malformed state, interrupted writes, cancellation cleanup, lock
  timeout/recovery, concurrent updates, and temporary-repository isolation.
